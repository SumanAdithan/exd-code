To bring the architecture together, the frontend `@exdcode/cli` package is wired to securely and strictly communicate with the backend `@exdcode/server` using Hono's RPC client.

## Implementation

### API Client (`api-client.ts`)
We initialize Hono's RPC client (`hc`) and export it for use throughout the CLI. By passing the `AppType` exported from the server package, the client instantly inherits end-to-end type safety for all routes, methods, and payloads.

```typescript title="packages/cli/src/lib/api-client.ts"
import { hc } from "hono/client";
import type { AppType } from "@exdcode/server";

export const apiClient = hc<AppType>(
  process.env.API_URL ?? "http://localhost:5000",
);
```

### Error Handling (`http-errors.ts`)
A dedicated utility is provided to parse standard `ErrorResponse` objects, safely extracting embedded JSON error messages from the backend or falling back to the standard HTTP `statusText`.

```typescript title="packages/cli/src/lib/http-errors.ts"
type ErrorResponse = {
  json: () => Promise<unknown>;
  status: number;
  statusText: string;
};

export async function getErrorMessage(response: ErrorResponse) {
  try {
    const data = (await response.json()) as { error?: string };
    if (typeof data.error === "string" && data.error.length > 0) {
      return data.error;
    }
  } catch {
    // Ignore invalid error payloads and fall back to the status text below.
  }

  return response.statusText || `Request failed with status ${response.status}`;
}
```

### `session.tsx`
The main session view now dynamically fetches the session data via the `:id` route parameter. It intelligently skips the loading phase if the data was prefetched via router state from `new-session.tsx`.
