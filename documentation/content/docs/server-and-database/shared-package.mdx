The `@exdcode/shared` package acts as the single source of truth for types, AI model definitions, and validation schemas. By keeping this in a dedicated package, both the CLI frontend and the Hono backend can guarantee type safety over the wire.

## Installation

The shared package relies on `zod` for robust runtime validation. Ensure it is installed into the correct workspace:

```bash
bun add zod --filter @exdcode/shared
```

## Folder Structure

```text
packages/shared/
├── package.json
├── tsconfig.json
└── src/
    ├── index.ts
    ├── models.ts
    └── schemas.ts
```

## Configuration

### `package.json`
The package is configured as a module and exposes `src/index.ts` as its main export.

```json title="packages/shared/package.json"
{
    "name": "@exdcode/shared",
    "type": "module",
    "private": true,
    "exports": {
        ".": "./src/index.ts"
    },
    "dependencies": {
        "zod": "^4.4.3"
    }
}
```

### `tsconfig.json`
Extends the base monorepo configuration for unified build settings.

```json title="packages/shared/tsconfig.json"
{
    "extends": "../../tsconfig.base.json",
}
```

### 2. Validation Schemas (`schemas.ts`)
Using Zod, we validate the data structures traversing the network. Most notably, we define the `ChatStreamEvent` which standardizes Server-Sent Events (SSE) payloads between the Hono server and the CLI.

```typescript title="packages/shared/src/schemas.ts"
import { z } from 'zod'

// Keep the explict key schema here because the one-argumant z.record(...) form
// does not type-check cleanly with the Zod typings used in this workspace.
export const toolCallArgsSchema = z.record(z.string(), z.json())

export const messagePartSchema = z.discriminatedUnion("type", [
    z.object({
        type: z.literal("reasoning"),
        text: z.string()
    }),
    z.object({
        type: z.literal("tool-call"),
        id: z.string(),
        name: z.string(),
        args: toolCallArgsSchema,
        result: z.string().optional()
    }),
    z.object({
        type: z.literal("text"),
        text: z.string()
    })
])

export const messagePartsSchema = z.array(messagePartSchema);

export type MessagePart = z.infer<typeof messagePartSchema>

// Tool-call args stay as nested JSON on the wire so the client does not need
// a second JSON.parse step after decoding the SSE event payload itself
export const chatStreamEventSchema = z.discriminatedUnion("type", [
    z.object({
        type: z.literal("text-delta"),
        text: z.string()
    }),
    z.object({
        type: z.literal("reasoning-delta"),
        text: z.string()
    }),
    z.object({
        type: z.literal('tool-call'),
        toolCallId: z.string(),
        toolName: z.string(),
        args: toolCallArgsSchema
    }),
    z.object({
        type: z.literal('tool-result'),
        toolCallId: z.string(),
        result: z.string()
    }),
    z.object({
        type: z.literal('done'),
        messageId: z.string(),
        durationMs: z.string()
    }),
    z.object({
        type: z.literal("error"),
        message: z.string()
    })
])

export type ChatStreamEvent = z.infer<typeof chatStreamEventSchema>
```
