The `@exdcode/database` package handles all data persistence for the application using Prisma ORM with a Postgres adapter. It utilizes Prisma's multi-file schema architecture to keep models and enums cleanly separated.

## Folder Structure

The database package is organized to separate the Prisma schema generation from the runtime Node.js client:

```text
packages/database/
├── prisma/
│   ├── models/
│   │   ├── enums.prisma
│   │   ├── message.prisma
│   │   └── session.prisma
│   ├── prisma.config.ts
│   └── schema.prisma
├── src/
│   ├── client.ts
│   ├── enums.ts
│   └── index.ts
└── package.json
```

## Prisma Configuration

### `package.json`
The database workspace is configured to generate the Prisma client into a local `generated/` directory, leveraging the new `@prisma/adapter-pg` for optimal Postgres performance.

```json title="packages/database/package.json"
{
  "name": "@exdcode/database",
  "type": "module",
  "private": true,
  "exports": {
    ".": "./src/index.ts",
    "./enums": "./src/enums.ts"
  },
  "scripts": {
    "db:generate": "bunx prisma generate"
  },
  "devDependencies": {
    "@types/node": "^26.1.0",
    "dotenv": "^17.4.2",
    "prisma": "^7.8.0"
  },
  "dependencies": {
    "@prisma/adapter-pg": "^7.8.0",
    "@prisma/client": "^7.8.0"
  }
}
```

### Base Schema (`schema.prisma`)
The base schema configures the generator and Postgres datasource.

```prisma title="packages/database/prisma/schema.prisma"
// This is your Prisma schema file,
// learn more about it in the docs: https://pris.ly/d/prisma-schema

// Get a free hosted Postgres database in seconds: `npx create-db`

generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "postgresql"
}
```

## Data Models

By leveraging Prisma's native multi-file support, the application's domain models are modularized into a `models/` directory.

### Enums
```prisma title="packages/database/prisma/models/enums.prisma"
enum Role{
    USER
    ASSISTANT
    ERROR
}

enum Mode{
    BUILD
    PLAN
}

enum MessageStatus{
    COMPLETE
    INTRUPTED
}
```

### Session Model
```prisma title="packages/database/prisma/models/session.prisma"
model Session{
    id String @id @default(cuid())
    userId String
    title String
    cwd String?
    createdAt DateTime @default(now())
    updatedAt DateTime @updatedAt
    messages Message[]
    
    @@index([userId])
}
```

### Message Model
```prisma title="packages/database/prisma/models/message.prisma"
model Message{
    id String @id @default(cuid())
    sessionId String
    role Role
    status MessageStatus
    model String
    content String
    parts Json?
    mode Mode
    duration Int?
    createdAt DateTime @default(now())
    session Session @relation(fields: [sessionId], references: [id], onDelete: Cascade)
    @@index([sessionId])
}
```

## Database Client

The runtime database client connects via the Postgres adapter and is cleanly exported for the rest of the monorepo.

### `client.ts`
```typescript title="packages/database/src/client.ts"
import "dotenv/config";
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "../generated/prisma/client";

const databaseUrl = process.env.DATABASE_URL;

if (!databaseUrl) {
  throw new Error("DATABASE_URL is not set");
}

const adapter = new PrismaPg({ connectionString: databaseUrl });

export const db = new PrismaClient({ adapter });
```

### `enums.ts`
```typescript title="packages/database/src/enums.ts"
export { Role, Mode, MessageStatus } from "../generated/prisma/enums";
```
